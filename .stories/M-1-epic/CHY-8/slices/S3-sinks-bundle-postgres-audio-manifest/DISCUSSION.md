## Answered here (no human needed)
- [AC3] Q: tables the Postgres sink writes? A: chars, words, word_chars, sentences, grammar_points, lessons, lesson_words, lesson_grammar, questions, content_versions; no `dictionary` table or link (parked: no AC, nothing loads it). Confidence 85%.
- [AC3] Q: write semantics? A: one transaction; mirror tables are upserted and rows missing from this import deleted; `questions` are upserted and never deleted; `content_versions` upserted with `imported_at` refreshed (advisor r1; `has` = latest row). Confidence 85%: content-schema.md:350.
- [AC3] Q: driver? A: sink takes a minimal `SqlClient` (`transaction`, `query`); tests use PGlite (Captain, 8.Q2), the CLI uses `pg` (devDependency; the build and CLI run in CI/Vercel, never in the browser). Confidence 80%.
- [AC3] Q: RLS in the migration? A: yes, `enable row level security` + `select to authenticated using (true)` on every table, no write policy; tests create the `authenticated` role first. If PGlite rejects it the executor reports; it never drops the RLS. Confidence 80%.
- [AC3] Q: where does the Postgres import run? A: not decided here: the CLI has `--sink postgres` reading `SUPABASE_DB_URL`; which pipeline calls it is promotion (rollout), not this slice. Confidence 85%.
- [AC3] Q: bundle body? A: `{ sha, lesson, sentences, questions, grammar, words, chars, gateCoverage, thin }`; sentences = lesson sentences + free sentences listed in a taught word's `examples`/`senses[].example` or a lesson grammar point lists in `examples`; words = the lesson's `sections.words.ids`; chars = every character of those words' `hanzi` that has a `content.chars` entry (h1-01: 你, 好, 们). Confidence 85%: ADR 0002 text.
- [AC3] Q: how does the app find the current sha? A: `<outDir>/current.json` = `{ sha }`, written last. Confidence 80%: CHY-25 consumes it; it is inside the static folder, so the service worker precaches it per deploy.
- [AC3] Q: bundle write atomic? A: write to `<outDir>/.tmp-<sha>`, rename to `<outDir>/<sha>`, then rewrite `current.json`; `has` = `current.json` holds `sha` and `<sha>/manifest.json` exists. Confidence 90%.
- [AC7] Q: manifest entry? A: `{ key, kind, ref, voice, hanzi, reading?, split? }`; a Word whose id differs from its hanzi is `split` and carries `reading` = its resolved spoken pinyin, which is the TTS input (Captain, 8.Q6). Confidence 85%.
- [AC7] Q: syllable clips? A: Pinyin Table = every syllables.yaml row × tones 1–4 with generated tone marks (a, e, ou rules), plus Primer `syllables`, `pairs` and `kind: 'syllable'` prompts keyed `sha256((spoken ?? text)|narrator)`; deduped, sorted by key. Confidence 85%: content-schema.md:321 and CHY-11's ask.
- [AC7] Q: where is the manifest computed? A: in `assemble` (adds `audio` to `ImportedContent`, so it is in the sha and in every sink); the bundle sink writes it as `audio-manifest.json`, Postgres fills `sentences.audio_key`. Confidence 85%.
- [CHORE] Q: build chain? A (Captain): production build = `pnpm import:content --sink bundle --only lessons/hsk1` → `pnpm fonts <outDir>/<sha> <fontsDir>` → `vite build`, in `scripts/build-content.sh`; `vercel.json` wiring moved to CHY-25 (see the delta answer below); CI's `pnpm build` stays as is and gains one memory-sink import step. `static/content/` is git-ignored. Confidence 80%.

A: the CLI expands it with `scopeFor` (roots + chars, sentences, syllables.yaml + the word/grammar files the lessons reference, Primer included; a non-vi/non-syllable `prompt.ref` adds `words/<ref>.yaml` only when that file exists, since lint 8 lets it name a sentence). `importContent` stays unchanged.
