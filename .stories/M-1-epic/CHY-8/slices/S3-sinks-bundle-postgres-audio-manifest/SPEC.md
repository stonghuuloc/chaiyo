# CHY-8 S3 — spec
ACs: AC3, AC7, LOC-10  ·  Repo: stonghuuloc/chaiyo  ·  rev 2 (delta vs main 477935b)

## Behaviour
- [AC3] `createBundleSink(outDir)` implements `Sink`. `write` produces `<outDir>/<sha>/<lessonId>.json` for every lesson and the Primer, `<outDir>/<sha>/manifest.json` = `{ sha, lessons: [{ id, file, bytes }] }` and `<outDir>/<sha>/audio-manifest.json`, then `<outDir>/current.json` = `{ sha }` last. It writes into `<outDir>/.tmp-<sha>` and renames, so a failed write leaves no `<sha>` folder and `current.json` unchanged. `has(sha)` is true when `current.json` holds `sha` and `<sha>/manifest.json` exists, so a revert A → B → A writes again: when `<sha>/` already exists `write` only rewrites `current.json`.
- [AC3] A lesson bundle is `{ sha, lesson, sentences, questions, grammar, words, chars, gateCoverage, thin }`: the lesson (its `ImportedLesson` without `gateCoverage` and `thin`, which sit at the top level), its sentences plus free sentences listed in a taught word's `examples`/`senses[].example`, its questions, its grammar points, the Words of `sections.words.ids` (derived fields included), every character of those words' `hanzi` that has a `content.chars` entry (h1-01: 你, 好, 们), the S1 gate coverage and the S4 thin entries; free sentences are also pulled in when a grammar point of the lesson lists them in `examples`. `assemble` and `buildBundle` pick these sentences through one exported function, `bundleSentences`, so `thin` (built by `assemble` from `bundleHanzi` over the same sentences) covers exactly the shipped seg. `buildBundle` copies `gateCoverage` and `thin` from the `ImportedLesson`; it never calls `thinEntries`. The Primer bundle has `words`, `chars`, `grammar` and `sentences` empty, `thin: []`, `gateCoverage: {}`. Every string the app renders for the lesson is in this JSON (CHY-13 reads all string values).
- [AC3] `createPostgresSink(sql)` implements `Sink` over a minimal `SqlClient` (`query`, `transaction`). One transaction writes `chars`, `words`, `word_chars`, `sentences`, `grammar_points`, `lessons`, `lesson_words`, `lesson_grammar`, `questions` and `content_versions`: mirror tables are upserted and rows absent from this import are deleted; `questions` are upserted and never deleted; `content_versions` is upserted (`sha` primary key, `imported_at` refreshed), so there is exactly one row per sha. `has(sha)` is true when `sha` is the row with the latest `imported_at` (the content the mirror holds now). Order: clear `lesson_words`, `lesson_grammar`, `word_chars`; delete stale `sentences`, `words`, `grammar_points`, `chars`; upsert `lessons`, `chars`, `grammar_points`, `words`, `sentences`; delete stale `lessons` (after `words` and `sentences` no longer point at them); re-insert the pair tables; upsert `questions`; upsert the version.
- [AC3] `supabase/migrations/<ts>_content_tables.sql` creates those 10 tables with the keys of content-schema.md:339-350 (the `dictionary` row :349 is parked) (`lessons` `(level, order)` unique) and RLS: `select` for `authenticated`, no write policy (privileges come from the Supabase defaults, which the test mirrors with `grant select, insert … to authenticated`). It runs from an empty database on PGlite.
- [AC3] Importing `fixtures/ok` into the memory sink, the bundle sink and the Postgres sink gives the same set of lesson ids, word ids, char hanzi, sentence ids and question ids in each (memory content, bundle files, SQL rows). Verified by: one test comparing, per entity, the fields (not only ids): word `spoken`/`hanviet`/`taughtIn`, sentence `spoken`/`seg`/`audio_key`, question `body`, char `readings`; each bundle file deep-equals `buildBundle(memory.content, id)`; `current.json.sha` equals the latest `content_versions` row. The memory content may hold more than the bundles (free sentences no word or grammar point lists, chars of untaught words, the Primer's missing words); the test names those differences.
- [AC3] Postgres re-import: twice → 1 `content_versions` row; A → B → A → `has(A)` true only after the third import and the mirror holds A again; a word removed from the content is gone from `words` and `lesson_words` after the next write; a question removed from the files is still in `questions`.
- [AC3] `pnpm import:content [dir] --sink memory|bundle|postgres [--out <dir>] [--only <roots>]` (`dir` default `content`) runs `importContent`, prints the sha as its last stdout line and exits 0; on `{ errors }` it prints `file  path  #check name  message` per error (the `lint:content` format) and exits 1. Lint refs come from `loadRefs()` as in `lint:content`.
- [AC3] Before any other step the CLI checks that `dir` is a directory; if not it prints `import-content: not a directory: <dir>` on stderr and exits 1 without calling `importContent` (S2 tester: `importContent('nope-dir', sink)` returns sha `273eec76…` of an empty content set).
- [AC3] The CLI never passes `--only` roots to `importContent` as given: `lintDir` `only` is a path-prefix filter, so `only: ['lessons/hsk1']` loads no words and no grammar and check 8 fails (167 errors on `content/` at 477935b). It passes `scopeFor(dir, roots)`: the roots + `chars`, `sentences`, `syllables.yaml`, and `words/<id>.yaml`, `grammar/<id>.yaml` for every id the lessons under the roots (Primer included) reference through the check 8(a) fields (`sections.words.ids`, question `tests.words`, and `prompt.ref` of a prompt whose kind is not `vi` or `syllable` when `words/<ref>.yaml` exists (such a ref may name a sentence; lint 8 accepts both), `sections.grammar.ids`, `tests.grammar`). For `content/` at 477935b that is 10 word files and `grammar/h1-g01.yaml`.
- [AC3] `--sink postgres` needs `SUPABASE_DB_URL`; when unset it exits 1 before reading any file.
- [AC7] `audioManifest(content)` computes one key, with entry shape `{ key, kind, ref, voice, hanzi, reading?, split? }`, per Sentence (lesson-inline and free) and per Word. Sentence voice = its `speaker` (CastId) else `narrator`; Word voice = `narrator`.
- [AC7] `key = sha256(hanzi|voice)` (hex): `你好！|redpanda` → 2499c461…, `你好|narrator` → a8c34d15…. A Word whose id differs from its hanzi (`打-da2`) is `split`: key = `sha256(id|voice)` and its entry carries `reading` = resolved spoken pinyin, the TTS input (8.Q6 C).
- [AC7] Syllable clips (docs rule, content-schema.md:321): every `syllables.yaml` row × tones 1–4 with generated tone marks (`ma` → `mā má mǎ mà`), every Primer card `syllables` and `pairs` entry (a string, or `{ say }` under CHY-11's C6: the key uses `say`) and every `kind: 'syllable'` prompt (`spoken ?? text`): key = `sha256(<that text>|narrator)`, `kind: 'syllable'`.
- [AC7] The manifest is deduped by key: among entries that share a key, the one with the smallest `kind`, then `ref`, is kept (fixtures/ok s-h1-01-10, s-h1-01-11 and s-w-1 are all `你好！` with no speaker and give one entry, `ref: 's-h1-01-10'`), then sorted by key. For a syllable entry `ref` = `hanzi` = the keyed text (`mā`). It lives in `ImportedContent.audio` (so it is in the sha and in every sink) and is written by the bundle sink as `audio-manifest.json` = `{ sha, entries }` (C5). Postgres `sentences.audio_key` is computed per sentence with the exported `audioKey(text, voice)`, never looked up in the manifest by `ref`.
- [LOC-10] `networkFirst` (src/service-worker/network.ts) awaits `cache.put` before it returns only when the request path is a bundle URL, `/content/<64 hex>/<file>.json`. For any other GET it hands `cache.put(…).catch(() => {})` to the fetch event's `waitUntil` and returns the response without waiting. A failed cache write never fails the response, and a non-ok response is never cached (both as today).
- [CHORE] `scripts/build-content.sh [dir]` (default `content`) runs `pnpm -s import:content <dir> --sink bundle --out static/content --only lessons/hsk1` (stdout teed to stderr so error lines stay visible), then `pnpm -s fonts static/content/<sha> static/fonts/lessons`; `static/content/` and `static/fonts/lessons/` are git-ignored. No `vercel.json` in this slice: real content does not pass the importer yet (see Not this slice), and nothing reads bundles before CHY-25. CI gains one step running the memory-sink import on `src/lib/content/import/fixtures/ok --only lessons/hsk1`, never on `content/`; `docs/content-schema.md` audio-key row gains the split-Word rule and "voice = the CastId; the Audio Renderer maps it to a provider voice".

- [AC7] `reading` for a split Word is its spoken pinyin; if VoiceStudio wants a different input, only the renderer changes (the manifest already carries `hanzi` and `reading`).
