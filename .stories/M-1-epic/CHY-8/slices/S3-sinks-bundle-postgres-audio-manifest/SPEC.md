# CHY-8 S3 — spec
ACs: AC3, AC7  ·  Repo: stonghuuloc/chaiyo  ·  rev 1

## Behaviour
- [AC3] `createBundleSink(outDir)` implements `Sink`. `write` produces `<outDir>/<sha>/<lessonId>.json` for every lesson and the Primer, `<outDir>/<sha>/manifest.json` = `{ sha, lessons: [{ id, file, bytes }] }` and `<outDir>/<sha>/audio-manifest.json`, then `<outDir>/current.json` = `{ sha }` last. It writes into `<outDir>/.tmp-<sha>` and renames, so a failed write leaves no `<sha>` folder and `current.json` unchanged. `has(sha)` is true when `current.json` holds `sha` and `<sha>/manifest.json` exists, so a revert A → B → A writes again: when `<sha>/` already exists `write` only rewrites `current.json`.
- [AC3] A lesson bundle is `{ sha, lesson, sentences, questions, grammar, words, chars, gateCoverage, thin }`: the lesson, its sentences plus free sentences listed in a taught word's `examples`/`senses[].example`, its questions, its grammar points, the Words of `sections.words.ids` (derived fields included), the chars of those words, the S1 gate coverage and the S4 thin entries; free sentences are also pulled in when a grammar point of the lesson lists them in `examples`. Every string the app renders for the lesson is in this JSON (CHY-13 reads all string values).
- [AC3] `createPostgresSink(sql)` implements `Sink` over a minimal `SqlClient` (`query`, `transaction`). One transaction writes `chars`, `words`, `word_chars`, `sentences`, `grammar_points`, `lessons`, `lesson_words`, `lesson_grammar`, `questions` and `content_versions`: mirror tables are upserted and rows absent from this import are deleted; `questions` are upserted and never deleted; `content_versions` is upserted (`sha` primary key, `imported_at` refreshed), so there is exactly one row per sha. `has(sha)` is true when `sha` is the row with the latest `imported_at` (the content the mirror holds now). Order: clear `lesson_words`, `lesson_grammar`, `word_chars`; delete stale `sentences`, `words`, `grammar_points`, `chars`; upsert `lessons`, `chars`, `grammar_points`, `words`, `sentences`; delete stale `lessons` (after `words` and `sentences` no longer point at them); re-insert the pair tables; upsert `questions`; upsert the version.
- [AC3] `supabase/migrations/<ts>_content_tables.sql` creates those 10 tables with the keys of content-schema.md:331-341 (`lessons` `(level, order)` unique) and RLS: `select` for `authenticated`, no write policy (privileges come from the Supabase defaults, which the test mirrors with `grant select, insert … to authenticated`). It runs from an empty database on PGlite.
- [AC3] Importing `fixtures/ok` into the memory sink, the bundle sink and the Postgres sink gives the same set of lesson ids, word ids, char hanzi, sentence ids and question ids in each (memory content, bundle files, SQL rows). Verified by: one test comparing, per entity, the fields (not only ids): word `spoken`/`hanviet`/`taughtIn`, sentence `spoken`/`seg`/`audio_key`, question `body`, char `readings`; each bundle file deep-equals `buildBundle(memory.content, id)`; `current.json.sha` equals the latest `content_versions` row. The memory content may hold more than the bundles (free sentences no word or grammar point lists, chars of untaught words, the Primer's missing words); the test names those differences.
- [AC3] Postgres re-import: twice → 1 `content_versions` row; A → B → A → `has(A)` true only after the third import and the mirror holds A again; a word removed from the files is gone from `words` after the next import; a question removed from the files is still in `questions`.
- [AC3] `pnpm import:content [dir] --sink memory|bundle|postgres [--out <dir>] [--only <roots>]` runs `importContent`, prints the sha as its last stdout line and exits 0; on `{ errors }` it prints `file  path  #check name  message` per error and exits 1. `--only` is expanded by `scopeFor(dir, roots)` (roots + `chars`, `sentences`, `syllables.yaml`, and `words/<id>.yaml`, `grammar/<id>.yaml` for the ids those lessons list). `--sink postgres` needs `SUPABASE_DB_URL`; when unset it exits 1 before reading any file.
- [AC7] `audioManifest(content)` returns one entry `{ key, kind, ref, voice, hanzi, reading?, split? }` per Sentence (lesson-inline and free) and per Word. Sentence voice = its `speaker` (CastId) else `narrator`; Word voice = `narrator`.
- [AC7] `key = sha256(hanzi|voice)` (hex): `你好！|redpanda` → 2499c461…, `你好|narrator` → a8c34d15…. A Word whose id differs from its hanzi (`打-da2`) is `split`: key = `sha256(id|voice)` and its entry carries `reading` = resolved spoken pinyin, the TTS input (8.Q6 C).
- [AC7] Syllable clips (docs rule, content-schema.md:312): every `syllables.yaml` row × tones 1–4 with generated tone marks (`ma` → `mā má mǎ mà`), every Primer card `syllables` and `pairs` entry (a string, or `{ say }` under CHY-11's C6: the key uses `say`) and every `kind: 'syllable'` prompt (`spoken ?? text`): key = `sha256(<that text>|narrator)`, `kind: 'syllable'`.
- [AC7] The manifest is sorted by key and deduped, lives in `ImportedContent.audio` (so it is in the sha and in every sink), is written as `audio-manifest.json` by the bundle sink, and fills `sentences.audio_key` in Postgres.
- [CHORE] `scripts/build-content.sh` runs `pnpm import:content --sink bundle --only lessons/hsk1`, then `pnpm fonts <outDir>/<sha> <fontsDir>`; `vercel.json` `buildCommand` = `scripts/build-content.sh && pnpm build`; `static/content/` is git-ignored; CI gains one step running the memory-sink import; `docs/content-schema.md` audio-key row gains the split-Word rule and "voice = the CastId; the Audio Renderer maps it to a provider voice".
