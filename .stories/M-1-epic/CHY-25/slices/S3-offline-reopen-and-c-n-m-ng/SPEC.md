## Behaviour
- [AC5] New `src/service-worker/shell.ts` exports `appShell(paths: string[]): string[]`: it returns the paths that do **not** start with `/content/`, in order. `src/service-worker/index.ts:9-11` becomes `const SHELL = appShell([...immutable, ...assets, ...prerendered].map((f) => new URL(f.path, self.registration.scope).pathname));`. On main this matters: a local `pnpm build` with `static/content` present emits a `service-worker.js` whose asset list holds `content/7915681c…/h1-01.json`, `content/current.json`, `fonts/lessons/ukai-*.woff2` — precaching every lesson, which makes an unopened lesson available offline and leaves AC6 with nothing to report. After the filter, `/fonts/lessons/…` stays precached (opened lessons need their font offline) and every `/content/` path is not. This reverses two frozen rules, both cited in D4: C3 rev 3 (`.stories/M-1-epic/CHY-10/slices/S2-prototype-parity/DISCUSSION.md:17`; `.stories/M-2-epic/WAVE-PLAN.md` "C3 (frozen rev 3)") and CHY-8 S3's decision that `static/` is precached per deploy (`.stories/M-1-epic/CHY-8/slices/S3-sinks-bundle-postgres-audio-manifest/DISCUSSION.md:7`).
- [AC5] `shell.ts` also exports `APP_SHELL = '/today'` and `cachedPage(cache, request, shellRequest): Promise<Response | undefined>` = `cache.match(request) ?? cache.match(shellRequest)`. `index.ts` installs `[...SHELL, APP_SHELL]` and, for a navigation request (`event.request.mode === 'navigate'`), calls `networkFirst` first; only when that throws and the exact URL is not cached does it return `cachedPage(...)` (`:29-38`). Online a navigation always takes the network response and caches it; the shell is a failure-only fallback, never a stale page served online. This is what makes AC5 pass after the normal flow: the learner reaches the lesson by client-side navigation, so no document request for the lesson URL is ever cached. `/today` is an `(app)` route and app pages are `ssr = false` (`src/routes/+layout.ts:7-8`), so its shell HTML is route-independent; `/` is the prerendered Landing Page and is not used.
- [AC5] `src/service-worker/network.ts:1` accepts `current.json` in the awaited set: `const BUNDLE = /^\/content\/(?:[0-9a-f]{64}\/[^/]+|current)\.json$/;`. The cache write for `/content/<sha>/<file>.json` and for `/content/current.json` is awaited before `networkFirst` resolves; every other GET still hands the write to `waitUntil` (`:12-14`, CHY-69's LOC-10 unchanged for them). Consequence: after an online `lesson('h1-01')` the current sha and the bundle are in the SW cache when the response resolves, so an immediate reload cannot miss the sha.
- [AC5] The offline read path: the install caches the `/today` shell; the online navigation/lesson caches the document (if requested), `current.json` and the bundle; an offline reload of `/lesson/h1-01/tu-moi` fails its document fetch, gets the shell from `cachedPage`, and the route's `catalog.lesson('h1-01')` gets both content files from the SW cache; `contentSha` is the same 64-hex sha. Nothing is read from IndexedDB or localStorage.
- [AC6] When a content request rejects and the cache has no entry, `httpSource` (S2) throws `CatalogError` code `offline` with the id it knows (for `current()` that is `current`). New `src/lib/catalog/view.ts` exports `lessonState(cat: Catalog, id: string): Promise<{ kind: 'ok'; content: LessonContent } | { kind: 'offline'; id: string }>`; it maps any code `offline` to `{ kind: 'offline', id }` using the lesson id the route asked for, and re-throws `not-found`/`malformed`.
- [AC6] `src/routes/(app)/lesson/[id]/[section]/+page.ts` loads `lessonState(catalog, params.id)`; `+page.svelte` renders the S2 title + word list for `kind: 'ok'`, and for `kind: 'offline'` renders only `m.lesson_offline()`. `messages/vi.json` gains `"lesson_offline": "Bài này cần mạng."`, which contains the AC's "cần mạng" (the page shows no empty lesson, no title, no word list).
- [AC6] A lesson that was opened online shows no notice offline (AC5); the notice appears only for a bundle absent from the cache. An unknown id stays `not-found` and is not reported as offline.
- [NFR] The cache name `shell-${version}` (`index.ts:8`) and the activate cleanup (`:17-23`) are unchanged; the sha URL stays immutable, so no per-bundle invalidation code is added. The awaited write applies to responses with `Cache-Control: no-store`; the Cache API stores them (HTTP cache directives do not govern `cache.put`).

## Negative controls
- Online `lesson('h1-01')`, then offline `lesson('h1-01')` -> same `contentSha` (AC5); offline `lesson('h0-00')`, never fetched -> `offline` and the page shows "Bài này cần mạng." (AC6).
- `current.json` cached but the bundle not -> `offline` (the sha does not imply the bundle); bundle cached but current.json evicted -> `offline` (the URL cannot be built).
- `appShell(['/_app/a.js', '/content/current.json', '/content/<sha>/h1-01.json', '/fonts/lessons/ukai-h1-01.woff2'])` returns the app and font paths and no content path.
- A navigation request for `/lesson/h1-01/tu-moi` with only `/today` cached: online it takes the network response and caches it (the shell is not used); offline it returns the `/today` response (the client-navigation flow). With neither cached, `cachedPage` returns `undefined` and the normal network-first failure propagates.
- A cached shell is never served online: the online navigation's response is the `fetch` result, not the cached `/today` body.
- `/` is never the fallback: `cachedPage` does not return the prerendered Landing Page for an app route.
- The existing non-bundle case still resolves before its `put` resolves (`network.test.ts:26-42`); the bundle case still awaits (`:9-24`).
- A `put` that rejects still returns the response; current.json gets the same protection as a bundle.
- The page must not flash "cần mạng" for a lesson that loads normally: `lessonState` returns `ok` with the content.
- `lessonState(cat, 'h9-99')` re-throws `not-found`; the notice is only for `offline`.

## Open assumptions
- [AC5] The server's document for `/today` is the same app shell as for `/lesson/...` because app pages are `ssr = false`; a route-specific head hint (modulepreload, nonce) is not content. Wrong pick: the fallback serves the wrong page and the manual shell check fails; the implementer reports it.
- [AC5] `GET /today` returns 200 at install (the auth guard is client-side, so the server returns the shell); a non-200 makes `cache.addAll` reject and the SW never installs. The install check is in the manual run.
- [AC6] The browser keeps the SW cache across an offline reload; only a new SW activation (a new deploy) drops `shell-${version}`. OS cache eviction can still remove an entry, and then the lesson is honestly offline-unavailable.
- [AC6] `Cache.put` accepts the `no-store` current.json response in the browser; the node test checks the `Cache` contract only. The Chrome manual run is the browser check.
- [AC5] `waitUntil` in `index.ts:36` still extends the event for non-bundle writes; the awaited current.json/bundle writes complete before `respondWith`'s promise settles, which is what AC5 compares.
